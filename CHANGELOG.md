# Changelog

Version lives in `package.json` (root, `client/`, `server/` — keep all three in sync) and is shown live in the app header (`client/src/App.jsx`, imported from `client/package.json`).

Versioning is loose semver, pre-1.0:
- **Patch** (0.1.x) — small fixes, copy tweaks, minor UI adjustments.
- **Minor** (0.x.0) — new features or workflows (a new dashboard section, a new job template, a new data source).
- Bump with every PR/session that ships a user-visible change, however small. Don't batch bumps.

## 0.5.0 — 2026-09-06

- New "ALIS Audit History" tool: pulls the Audit History widget (Note/Updated At/Updated By) directly from ALIS's own Community Profile, Resident Profile, and Company pages — any mix of company-wide, one or more communities, one or more residents — with the same filters ALIS's own widget offers (date range, Updated By, Type, Notes search), combined into one timestamp-sorted feed for cross-referencing activity. On-screen dashboard (Combined + per-target tabs), Excel export, and PDF export. A new destination is a one-line registry addition, not new scraping code.
- Weekly Wellness Scorecard: undocumented-incident rows (falls, elopement, behavioral, other incidents) now name who reported each open incident, not just a count — new use of the Integration API's staff attribution (previously unused this session).
- Company/Community ALIS Usage Audit: Care Tracking's Enabled column now also checks the community's live Care Tracking page as corroboration (same idea as last week's Daily Stand-Up signal) — currently returns 0 for every community due to that page's DOM not being table-based like Daily Stand-Up's; documented as a known limitation rather than hidden, and provably harmless in the meantime (can only ever fail to help, never flip a correct answer to a wrong one).
- New "Evaluation Lookup" tool (top-nav, not a job): search a resident by name within an ALIS host, see their current evaluation's CarePoints/Care Level/Fee plus a question-by-question answer breakdown where the underlying RET config version happens to be cached.

## 0.4.0 — 2026-09-06

- Weekly Wellness Scorecard: new "Average CarePoints (acuity) per current evaluation" row, sourced from a `carePoints` field ALIS already populates on `/v1/export/residents/evaluations` (confirmed live — Memory Care residents average meaningfully higher than Assisted Living, as expected). "Falls with injury (head) / hospital transfer" flipped from always-manual to computed for the hospital-transfer half, reading the real `taken_to_hospital` flag off a completed Incident Report Form via the previously-unwired `/v1/export/residents/incidents/{id}/formData` endpoint — the "head injury" qualifier still isn't captured (no such field exists on the generic form template). A run where formData comes back empty despite a fall's forms being marked complete now surfaces as a data-quality warning rather than a silent, misleadingly-clean zero.
- New per-company reporting toggle (`server/services/companyFeatures.js`): Sentinel-tagged incidents (Leisure Care's own ALIS incident-type configuration marks specific high-severity variants — Elopement, Death (Unexpected), Abuse/Neglect, Suicide Attempt, etc. — with "Sentinel" in the type name) now get their own row on the Weekly Wellness Scorecard, their own flag + PPTX slide on the KPI/QBR pipeline, hidden entirely for every other client rather than shown as a always-zero row.
- Company/Community ALIS Usage Audit: "Daily Stand-up" now has a real usage signal for the first time (previously always "—", no export endpoint or entitlement flag exists for it) — a live Playwright scrape of each community's own Daily Stand-Up report page, logged in per-host since a community subdomain doesn't share admin.alisonline.com's session (confirmed live: same `ALIS_USERNAME`/`ALIS_PASSWORD` admin credentials work directly against it). Retries once on the transient network errors headless Chromium occasionally throws on first navigation to a new host.
- New ALIS API wrappers (`server/services/alisApiClient.js`): `getIncidentsV2` (Integration API — richer than the deprecated export incidents endpoint, includes staff attribution; not yet wired into a specific report), `getIncidentFormData`, `getEvaluationConfigurations`, `getEvaluationXmlDocuments`. New `server/services/evaluationScoring.js` parses RET evaluation question/answer XML into readable text (built for a future resident-evaluation detail view, not yet wired into a report) plus a `evaluation_config_versions` DB cache so a since-superseded evaluation config's answer catalog isn't lost once ALIS's export moves on to a newer version.

## 0.3.0 — 2026-08-31

- QBR dashboard: Support & Context's HubSpot Tickets panel now lists open tickets individually, each linked straight to HubSpot (sorted worst-aging first) — alongside the existing total/category summary, so a ticket can be worked and closed without leaving the dashboard. New "🔄 Refresh HubSpot" button re-pulls live ticket/deal data and regenerates flags in place, so closing something during meeting prep flows through to the dashboard and the next PPTX export without re-running the whole kpi-export job (new `POST /api/qbr/:jobId/refresh-hubspot`). Also fixed the HubSpot Deals panel truncating long deal names into unreadable/unclickable text — names now wrap onto their own line instead of being squeezed into a single-line flex row.
- KPI Export: per-community pulls (occupancy, order administration) now run with bounded concurrency (4 at a time) instead of one community at a time — observed live on a 46-community account taking 2+ hours sequentially (~170s/community × 46). Concurrency limit is deliberately conservative since ALIS doesn't document a rate limit for these specific endpoints (only for the unrelated invoiceCharges streaming endpoint); raise `COMMUNITY_CONCURRENCY` in kpiExport.js if a real run shows no errors at this level.

- QBR dashboard: new Days Sales Outstanding (DSO) KPI — company average with green/yellow/red conditional formatting (≤11d / 11-30d / >30d), a monthly trend chart, and a drill-down drawer breaking DSO out by Region, Facility, and Resident. Formula: `(AR balance ÷ Billed revenue) × Days`, computed per invoice cohort (bucketed by each invoice's own `invoiceDate`) since ALIS's outstanding-invoices endpoint only exposes a point-in-time AR balance, not historical month-end balances.
- New `dso_snapshots` table: every kpi-export job now persists company/region/community DSO rows, giving a real month-over-month/quarter-over-quarter/year-over-year trend as more jobs run for the same company — the first real cross-job time-series query in the app (every other KPI lives in one JSON blob per job with no history). New `GET /api/qbr/:jobId/dso-history` endpoint serves it.
- Communities now carry their ALIS `region` field (previously discarded during community resolution) — the first region-aware rollup in alis-hub, which has otherwise been a flat company→community model.
- New `Drawer` component (`client/src/components/Drawer.jsx`), extracted from the job-list's `JobDrawer`, and the DSO drill-down's Company/Region/Facility/Resident + trend-history pattern — both are meant as the template for bringing the same drill-down to other KPI sections (occupancy, staffing, etc.) next, not yet done in this pass.
- Occupancy: accounts that don't populate ALIS's floor-plan/room module now show a clear "not tracked in ALIS" message instead of a bare "—" (new `hasOccupancyData` flag, same pattern as `hasBillingData`/`hasEvaluationData`). Also fixed a bug where a genuine total occupancy-pull failure (every month erroring, not just returning no data) was silently reported as job success and never surfaced anywhere — it's now both a job-item failure and a dashboard data-warning, the same as every billing endpoint already gets.
- QBR PPTX export: Client Overview slide redesigned (report-metadata pills, a wrapped community list instead of one run-on line, a boxed "Account Notes" area) to fill what was previously a mostly-blank slide. Support Review now lists tickets individually — separated into Open/Recently Closed, each linked straight to its HubSpot record, with any next-step from an imported account-health-export carried through onto open tickets. New "HubSpot Deals" slide does the same for the live HubSpot deal pipeline (open/closed, linked, with stage and amount) — previously pulled but never actually rendered anywhere in the deck.
- QBR dashboard: new Revenue Yield (PPD) KPI — billed revenue per occupied day and per physical-census day, company average with Region/Facility drill-down and month-over-month trend (new `ppd_snapshots` table, `GET /api/qbr/:jobId/ppd-history`, same pattern as DSO). The census-day figure is a genuinely distinct number from occupied-day (not an approximation) — confirmed against real ALIS occupancy data that a unit can be billed/held while a resident is on a hospital stay or leave of absence, so census undercounts occupancy in ~2% of occupied days. Also added as a line on the QBR PPTX's Financial slide.
- Both the QBR PPTX and the Weekly Wellness Scorecard PDF now end on a shared ALIS contact-info page (email, phone, mailing address, Helpdesk link, and the ALIS platform-updates email sign-up link) — kept in sync via new `server/services/alisContactInfo.js` rather than duplicated copy in each export.

## 0.2.0 — 2026-08-23

- KPI Export / QBR pipeline: multi-host account support, ALIS billing data (recurring/invoiced revenue, AR aging, revenue-leakage detection), admissions/discharges and levels-of-care KPIs, HubSpot company autocomplete + persistent subdomain learning for New Job.
- QBR dashboard: Alerts & Flags broadened beyond clinical quality to account/usage/financial signals, HubSpot Service/Financial health import (`account-health-export` skill bridge), data-availability-aware sections (hide unused modules, show genuine zeros as positive callouts).
- QBR PPTX export: visual redesign, native charts, ALIS billing include/exclude toggle.
- New Job: attaching the health-export skill's JSON to a kpi-export job is now additive to the form (company/subdomain/period dates are always required alongside it, not an either/or with a raw-JSON mode).
